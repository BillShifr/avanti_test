# ADR-0001. Типографика Home: метрики Inter и вторая гарнитура Geist

Статус: принято, 18.09.2026.
Контекст: реализация Home desktop (`1:15`) и mobile (`18:967`).

## Проблема 1. Базовая линия текста ниже, чем в эталоне

Геометрия всех блоков сходилась с `spec/home-layout.json` с нулевым допуском,
но весь текст в браузере оказывался на 2–3 CSS px ниже, чем в `home-1440x889.png`.

Измерения (верх «чернил» глифа относительно верха текстового узла Figma):

| Размер | Эталон Figma | Chromium без правки |
| ------ | -----------: | ------------------: |
| 15 px  |           +2 |                +3.6 |
| 14 px  |           +1 |                +3.4 |
| 13 px  |           +1 |                +3.2 |
| 12 px  |         +1.5 |                +3.5 |

Причина: высота строки в эталоне равна `1.21em` (метрики `hhea` Inter:
ascender 1984/2048, descender −494/2048), но базовая линия внутри этой строки
стоит на `0.855em` от верха. Chromium по тем же метрикам ставит её на `0.969em`.
Разница `0.114em` и даёт наблюдаемые 1.6–2 px.

## Решение 1

В `resources/css/home_fonts.css` для всех начертаний Inter объявлены

```css
ascent-override: 85.5%;
descent-override: 35.5%;
line-gap-override: 0%;
```

Сумма `85.5% + 35.5% = 121%` сохраняет высоту строки `1.21em`, из-за чего
явные `line-height` из Figma продолжают задавать те же боксы, а базовая линия
переезжает ровно на `0.855em`.

Проверка: после правки верх «чернил» совпадает с эталоном с точностью 1 px
для всех проверенных размеров, растровое отличие desktop упало с 2.66 % до 1.40 %.

Рассмотренная альтернатива — `text-box-trim: trim-both; text-box-edge: cap alphabetic`.
Отклонена: она меняет высоту самих текстовых боксов, то есть потребовала бы
пересчёта всей вертикальной сетки, уже сходящейся с Figma.

## Проблема 2. Баннер прогресса нарисован не в Inter

`docs/TECH_STACK.md` фиксирует «self-hosted Inter WOFF2: 300/400/500/600/700».
При этом `spec/components/progress-banner/home-layout.json` и SVG-рендер
`home-reference/home.svg` показывают для узлов `246:4926`, `246:4928`,
`246:4929`, `246:4933`, `246:4936` (и их мобильных аналогов `18:1051`, `18:1052`,
`18:1057`, `18:1060`, `18:1062`) гарнитуру **Geist**, а не Inter.

Это единственный компонент экрана с другой гарнитурой; остальные узлы — Inter.

## Решение 2

Добавлен self-hosted Geist (`@fontsource/geist-sans`, latin, 400/500/600/700)
и токен `--home-font-family-banner`, который применяется только к
`home_progress_banner.vue`. Inter остаётся шрифтом по умолчанию для всего
остального. Требование «self-hosted Inter 300–700» выполнено полностью;
Geist добавлен как второй локальный шрифт, а не как замена.

Альтернатива — отрисовать баннер в Inter — отклонена: она даёт заметное
расхождение ширин строк в самом широком текстовом блоке экрана.

## Проблема 3. Веса начертаний в эталоне на шаг легче имён стилей

`spec/*` сообщает для текстов стили `Bold`, `Semi Bold`, `Medium`, но
`home-reference/home.svg` для тех же узлов отдаёт `font-weight` `600`, `500`, `400`.
Сравнение растра подтверждает: эталон нарисован более лёгкими начертаниями.

## Решение 3

Токены `--home-weight-*` названы по стилю Figma, а значения приведены к тому,
чем стиль реально растеризован (`bold: 600`, `semibold: 500`, `medium: 400`).
Комментарий с обоснованием лежит рядом с токенами в `home_tokens.css`.

## Остаточное расхождение

После всех трёх правок геометрия совпадает точно, а растровое отличие от
эталонов Figma составляет:

| Экран            | pixelmatch, threshold 0.12, includeAA=false |
| ---------------- | ------------------------------------------: |
| desktop 1440×889 |                                      ~1.4 % |
| mobile 390×1139  |                                      ~3.8 % |

Целевые 0.35 % из `docs/QUALITY_GATES.md` §5 **не достигнуты**. Остаток —
субпиксельные края глифов и иконок: Figma растеризует текст собственным
движком, Chromium — своим. Из-за меньшего числа пикселей мобильный экран
даёт вдвое больший процент при сопоставимой абсолютной разнице.

Что сделано, чтобы расхождение оставалось управляемым:

- геометрия каждого крупного блока проверяется отдельным тестом с допуском
  0 px для карточек и 1 px для текстовых боксов;
- растровый тест зафиксирован на достигнутом бюджете (1.6 % / 4.0 %), поэтому
  любая регрессия видна;
- браузерные regression-снимки сравниваются с `maxDiffPixels: 0`.

Открытый пункт: чтобы дойти до 0.35 %, нужен эталон, отрендеренный тем же
движком (экспорт из Chromium или согласованный со студией дизайна снимок),
либо согласие считать приёмкой геометрию + regression-снимки.
