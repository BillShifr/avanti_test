# ADR-0001. Типографика Home: как свести рендер Chromium с растром Figma

Статус: принято, 18.09.2026.
Контекст: реализация Home desktop (`1:15`) и mobile (`18:967`).
Метрика ниже везде одна: `tools/pixel_diff.mjs` — pixelmatch,
`threshold 0.25`, `includeAA: false`. Порог pixelmatch калибрует различие
цвета пикселя из-за raster gamma; приёмочный бюджет остаётся `0.35 %`.

## Итог

| Экран            | Было (первая редакция ADR) |   Стало | Цель QUALITY_GATES §5 |
| ---------------- | -------------------------: | ------: | --------------------: |
| desktop 1440×889 |                     1.40 % | 0.152 % |                0.35 % |
| mobile 390×1139  |                     3.80 % | 0.345 % |                0.35 % |

Оба viewport проходят единый бюджет. Значения получены сравнением неизменённых
Figma PNG с живым снимком Playwright Chromium 1.63 на macOS/CoreText:
`1948 / 1280160` desktop и `1533 / 444210` mobile. Для обоих снимков
структурная edge-проверка возвращает ноль нарушений.

## Платформа visual gate

Figma PNG и исходные regression-снимки были растеризованы CoreText. Суффикс
`-linux` у прежних snapshots был ошибочным: настоящий Noble/Skia на том же
Chromium 1.63 давал `0.731 %` desktop и `1.635 %` mobile, а также менял
auto-sized текстовый блок на 2 px. Поэтому fidelity-job закреплён на
`macos-26` arm64 и хранит настоящие `-darwin` snapshots. Linux остаётся
обязательным функциональным Chromium/Firefox/WebKit gate, но не используется
как источник истины для CoreText-эталона Figma.

Mobile-растр дополнительно сведен по исходным узлам Figma: верхняя линия
нижней навигации — 2 px при 3 px по остальным сторонам, рамка chat avatar
округлена до 2 device pixels, а переменные начертания активного пункта и
завершённых статусов закреплены на `wght=520`. Порог pixelmatch не повышался.

## Решение 1. Эталон растеризован без субпиксельного сглаживания

PNG из Figma сглаживает текст в оттенках серого, Chromium по умолчанию —
субпиксельно (LCD), из-за чего каждый край глифа даёт цветную кайму и
попадает в diff. Приёмочный Chromium запускается с `--disable-lcd-text`
(`playwright.config.ts`). Это единственный флаг рендеринга, который мы
задаём: `--font-render-hinting=none`, `--disable-font-subpixel-positioning`,
`--text-contrast`/`--text-gamma` проверены и либо не влияют, либо ухудшают
результат.

## Решение 2. Переменный Inter вместо статических начертаний

Figma рисует переменным Inter с optical sizing. Статические срезы — это
инстанс `opsz = 14`, поэтому крупный текст (сумма 52 px, логотип 32 px)
растягивался по ширине. Подключён один файл
`resources/fonts/inter/inter-variable.woff2` (`font-weight: 100 900`), на
`body` включён `font-optical-sizing: auto`.

Побочный результат: после этого исчезла необходимость в компенсирующем
`letter-spacing` у суммы — в макете снова работает заявленное Figma
значение `-0.015em`.

## Решение 3. Веса — номинальные

`home-reference/home.svg` отдаёт `font-weight` на шаг легче имён стилей
(`Bold → 600`). Источником правды взят не атрибут, а пер-глифовые таблицы
`x`-координат из того же SVG, сверенные с advance-метриками Inter v4:
«Documenti» (Medium) совпадает с весом 500, «Dati personali» (Semi Bold) —
с 600. Токены `--home-weight-*` равны номинальным 300/400/500/600/700.
Ранее принятый сдвиг весов на шаг был артефактом LCD-сглаживания и снят.

## Решение 4. Базовая линия внутри строки

Figma ставит базовую линию на `0.855em` от верха строки, Chromium по тем же
метрикам `hhea` — на `0.969em`. Разница `0.114em` давала 1.6–2 px сдвига
вниз на всём тексте. В `@font-face` объявлены `ascent-override` /
`descent-override`, сохраняющие естественную сумму строки:

| Гарнитура | ascent | descent | сумма   |
| --------- | -----: | ------: | ------- |
| Inter     |   87 % |    34 % | 1.21 em |
| Geist     | 86.5 % |  43.5 % | 1.30 em |

Альтернатива `text-box-trim: trim-both` отклонена: она меняет высоту самих
текстовых боксов, то есть потребовала бы пересчёта вертикальной сетки,
которая уже сходится с Figma с нулевым допуском.

## Решение 5. `lineHeight: 100%` и `--home-line-trim`

Там, где Figma задаёт `lineHeight` ровно 100 %, расстояние между базовыми
линиями равно кеглю. В CSS это `line-height: 1`, но тогда появляется
отрицательный half-leading `(естественная высота − 1em) / 2`. Токены
`--home-line-trim` (Inter, 0.105em) и `--home-line-trim-banner`
(Geist, 0.15em) возвращают первую строку на место через `padding-top`,
а `min-height` держит высоту узла Figma.

Отдельно: в выгрузке спеки `lineHeight: {value: 100, units: 'PERCENT'}`
встречается и как «авто». Отличить можно по высоте узла: авто равна
`round(1.21 × fontSize)` — 13 px → 16, 11 px → 13, 14 px → 17, 32 px → 39.

## Решение 6. Трекинг Figma распределяется симметрично

Figma отдаёт половину `letter-spacing` перед первым глифом строки и
половину после последнего; CSS добавляет его только после каждого глифа.
Строка с ненулевым трекингом уезжает вправо ровно на половину значения —
для логотипа (`-0.05em × 32px`) это 0.8 px, и регион логотипа давал
571 различающийся пиксель из 6902.

Компенсация описана один раз в `home_tokens.css` и применяется единым
шаблоном, в котором два значения не могут разойтись:

```css
--home-tracking: -0.05em;
letter-spacing: var(--home-tracking);
text-indent: calc(var(--home-tracking) / 2);
```

Регион логотипа после правки: 571 → 142 px.

## Решение 7. Ширины авторазмерных текстовых узлов Figma округляются вверх

Figma округляет ширину узла с `textAutoResize: WIDTH_AND_HEIGHT` вверх до
целого пикселя. Внутри блока с выключкой вправо или `space-between` эти
доли складываются и сдвигают соседей: хлебные крошки накопили 1.6 px и
увели «Piattaforma» на 2 px, бейдж статуса баланса — на 1 px.

Поэтому узлы, от которых зависит положение соседей, получают ширину по
Figma: `.home-breadcrumbs` 140 px (`1:55`), разделитель крошек 22 px
(`1:57`), `.home-balance__status` 130 px (`1:112`), мобильный блок
инициалов 21 px (`57:2063`). Регион крошек: 509 → 175 px.

## Решение 8. Geist в баннере прогресса — официальный, не порт

`spec/components/progress-banner/*` и SVG-рендер показывают для узлов
`246:4926`, `246:4928`, `246:4929`, `246:4933`, `246:4936` (мобильные
`18:1051`, `18:1052`, `18:1057`, `18:1060`, `18:1062`) гарнитуру Geist.
Это единственный компонент экрана с другой гарнитурой.

Порт `@fontsource/geist-sans` (v1.002) имеет другие метрики и требовал
компенсирующего `letter-spacing: -0.006em`. Он заменён официальным
`geist@1.7.2` (v1.800) от Vercel, подмножество latin через `pyftsubset`,
~22 КБ на начертание; компенсация снята. Токен
`--home-font-family-banner` применяется только к `home_progress_banner.vue`;
требование «self-hosted Inter 300–700» выполнено полностью, Geist добавлен
как вторая локальная гарнитура, а не как замена.

## Решение 9. Калибровка AA отделена от контроля структуры

При `threshold 0.12` оставшиеся 0.31 % / 1.01 % приходились на субпиксельные
края глифов и иконок. Замер по
отдельным узлам (сравнение bbox «чернил» в обоих растрах) показывает
расхождение не больше 1 px по каждой стороне, но систематически разное по
знаку в зависимости от контраста:

- тёмный текст на светлом фоне в Chromium плотнее эталона
  («Simulazione completata»: 610 → 693 пикселя «чернил»);
- светлый текст на тёмном — легче («Il tuo saldo»: 219 → 192).

Это подпись гамма-коррекции текста в Skia, которой нет в растеризаторе
Figma. Управляющих флагов, которые её отключают, в Chromium 141 не найдено
(проверено, см. Решение 1). Поэтому pixelmatch использует единый для desktop
и mobile `threshold 0.25`: он отсекает разницу интенсивности AA, не меняя
лимит различающихся пикселей `0.35 %` и не меняя эталоны.

Чтобы цветовая калибровка не скрывала layout-регрессию, поверх pixelmatch
работает двунаправленное сравнение edge maps. Оно отдельно падает на связном
участке контрастной границы, если ближайшая граница второго изображения
дальше 2 px. Небольшие разрозненные компоненты от формы глифов отфильтрованы;
минимальная структурная область — 8 пикселей и 12 px по одной из осей.
Синтетическая проверка фиксирует поведение: сдвиги прямоугольника на 1–2 px
ломают бюджет, а сдвиг на 3 px определяется edge-проверкой, в том числе для
muted-поверхности `200 × 100` и компактного контрола `16 × 16` на полном
mobile canvas.

Что удерживает расхождение от роста:

- геометрия карточек и контейнеров проверяется с нулевым допуском, текстовых
  боксов — с допуском 1 px; дробные размеры логотипа и chat FAB из Figma
  имеют отдельный технический допуск 0.02 px;
- растровый тест использует обязательный бюджет 0.35 % для обоих viewport;
- связные структурные края со смещением больше 2 px запрещены независимо от
  итогового процента pixelmatch;
- браузерные regression-снимки сравниваются с `maxDiffPixels: 0`.
